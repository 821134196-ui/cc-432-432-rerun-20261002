# 布卷疵点复检与退修系统（millinspect）

面向纺织厂质检车间的布卷全流程管理：**入检 → 初检登记 → 疵点按米数定位（附照片）→ 复检 → 退修（生成新版本）→ 分级放行**。

零第三方依赖，仅使用 Python 3.10+ 标准库 + SQLite + 原生 HTML/CSS/JS。

## 单条命令启动

```bash
./run.sh            # 默认 http://127.0.0.1:8000，自动重置并播种演示数据
./run.sh 8080       # 指定端口
```

或手动：

```bash
python3 -m millinspect.app --reset --seed --port 8000
```

演示数据包含 7 个布卷编号（B-240901 ~ B-240907），覆盖待检、初检中、
复检队列（含已接收/已超时）、退修新版本（V1→V2）、长度不足折价放行、
断经退修后 B 级修复品放行、照片缺失待补照等全部场景。

## 六个界面

| 标签页 | 内容 |
|---|---|
| 布卷台账 | 入检登记（长度/幅宽/颜色批次/来源机台）、在册布卷状态 |
| 检验录入 | 固定显示**当前米数**与**幅宽**的 HUD、检验段登记、疵点按米数录入+照片上传、补照 |
| 疵点地图 | 布卷**横向长度条**，检验段虚线分带，疵点按位置落点（按等级着色），版本链 |
| 复检队列 | 派发（只引用原检验段）、接收、确认无碍/确认问题、超时提醒角标 |
| 退修进度 | 开单→开工→完成生成新版本（V2/V3…），显示版本关联 |
| 放行记录 | 放行条件校验（等级+原因清单）、分级放行、历史记录 |

配色：亚麻色（底）、板岩灰（结构）、锈红（警示/重点）。
放行状态同时使用**色标**（圆点徽标）与**文字**。

## 业务规则

- **检验段区间**：起点≥0、终点>起点、不得越出布卷长度、同版本区间不得重叠（首尾相接允许）；疵点位置必须落在所属段区间内。
- **复检引用**：复检任务只能引用**当前版本**的原检验段；退修生成新版本后，旧版本段不可再派发复检。
- **复检人约束**：复检人与该段初检人不能相同。
- **接收竞争**：同一布卷同一时刻只允许一条复检任务被接收；两条复检线同时接收时，服务层以锁 + `BEGIN IMMEDIATE` 条件更新保证恰好一条成功（另一条 409）。
- **退修版本**：退修完成生成 `post_repair` 新版本（V2、V3…），记录 `supersedes` 与退修工单；**已放行布卷不能直接改为待检/退修**。
- **分级放行**：
  - A 级（断经）：必须退修，并在新版本上复检确认清除；
  - B 级（色差/污渍）：须退修后复检确认；长度不足可复检确认后**折价放行**（不退修，<98% 自动附折价比例）；
  - C 级（照片缺失/其他）：照片缺失必须补照，其余须复检员书面确认；
  - 有未完成/超时未重派的复检任务一律拦截。
- **照片权限**：照片存本地目录，库中只存路径；仅**已接收且进行中**任务的复检人可申请时效令牌（30 分钟）读图；任务完成/超时后令牌立即失效（HTTP 403）。
- **复检超时**：进程内巡检线程每 3 秒扫描 `due_at`，超时任务自动转 `timeout`，需重新派发；旧超时在新任务完成后不再拦截放行。

## 数据存储

- SQLite：`<数据目录>/millinspect.db`（布卷、检验版本、检验段、疵点元数据、复检任务、退修工单、放行记录、照片令牌）
- 照片文件：`<数据目录>/photos/defect-<id>-<随机>.<ext>`

## API 摘要

```
GET  /api/meta /api/bolts /api/bolts/{code} /api/queue /api/repairs /api/releases
GET  /api/release-check?bolt=B-240901
GET  /api/photo?token=<令牌>            # 200 image/* 或 403
POST /api/bolts
POST /api/bolts/{code}/inspection
POST /api/versions/{id}/segments
POST /api/segments/{id}/defects         # photo_data 为 base64
POST /api/defects/{id}/photo            # 补照
POST /api/queue                         # 派发复检
POST /api/tasks/{id}/claim | /complete | /photo-grant
POST /api/repairs  /api/repairs/{id}/start  /api/repairs/{id}/finish
POST /api/releases
```

错误码：400 业务规则、403 照片权限、404 不存在、409 状态/接收冲突。

## 测试

```bash
python3 -m unittest discover -s tests -v
```

55 个用例覆盖：

- **位置区间**：越界/零长/负起点/重叠/相邻相接/疵点落点边界/无照片/补照；
- **版本关联**：退修 V1→V2→V3、supersedes、复检只能引用当前版本原段、已放行不可回退、跨卷引用；
- **接收竞争**：复检人≠初检人、双任务单卷只允许一条、同任务与跨任务的**多线程并发**恰好一成一败、完成后下一条可接收、超时拦截与重派放行；
- **放行条件**：A/B/C 各级正反路径、折价比例文案、未完成任务拦截、重复放行；
- **照片权限**：服务层与 HTTP 层 403→200→完成后 403、令牌过期、跨卷/非接收人拒绝、后台超时巡检线程。

## 目录结构

```
millinspect/
  db.py        # SQLite schema、连接与事务
  domain.py    # 疵点字典、分级放行规则、异常
  service.py   # 领域服务（全部业务规则、超时巡检线程）
  photos.py    # 本地照片存储、演示用 PNG 生成
  demo.py      # 演示数据播种
  app.py       # 标准库 HTTP 服务 + JSON API
  static/      # index.html / styles.css / app.js
tests/         # unittest 测试
run.sh         # 单条本地启动命令
```
