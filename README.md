# 布卷疵点复检与退修系统

纺织厂布卷质量管理：布卷入检 → 疵点按米数定位（附照片）→ 复检隔离 → 退修生成新版本 → 分级放行。
仅依赖 Python 3.9+ 标准库；SQLite 存布卷与检验版本，本地目录存疵点照片，进程内守护线程生成复检超时提醒。

## 单条本地启动命令

```bash
python3 app.py --reset --demo
```

- 首次启动自动写入演示数据：5 个布卷（待复检、复检超时、退修后 v2 放行、已放行、初检进行中）与演示照片。
- `--demo` 额外自动创建一条全新布卷并走通 **初检 → 复检接收 → 复检提交 → 放行** 样例。
- 浏览器打开 http://localhost:8000 （可选 `--port` / `--host`）。

照片访问需要检验人员身份：先在右上角选择/填写当前人员（如 `赵复检`），再点击疵点照片。

## 六个业务视图

| 视图 | 内容 |
|---|---|
| 布卷台账 | 长度、幅宽、颜色批次、来源机台、当前版本、状态色标+文字、版本链详情与放行入口 |
| 检验录入 | 检验段与疵点录入；顶部固定显示当前米数 / 布卷总长 / 幅宽 / 初检人 |
| 疵点地图 | 布卷以横向长度条呈现，疵点按米数落点（A 锈红 / B 赭黄 / C 板岩灰），点击看照片 |
| 复检队列 | 接收、复检判定（确认 / 误判 / 转退修）、超时重新下发 |
| 退修进度 | 工单开工、修复 / 核减长度、上传修复照片，完工自动生成新版本 |
| 放行记录 | 分级放行条件、专项处理说明、历次放行依据 |

配色：亚麻色底 + 板岩灰导航 + 锈红强调；放行状态同时用色标和文字呈现。

## 核心业务规则

- **位置区间**：检验段必须落在布卷长度内且互不重叠；疵点米数必须位于所属检验段内。
- **复检引用约束**：复检只能引用初检（v1）检验段上的疵点；退修后生成新版本（v2、v3…），
  新版本修复记录通过 `source_segment_id` 回指原检验段，米数随快照保留。
- **终态保护**：已放行布卷不能直接改回待检；只能由退修新版本承接。
- **接收竞争**：同一布卷任一时刻至多一条 open 复检任务（部分唯一索引 + 条件 UPDATE），
  两条产线同时接收只有一条成功。
- **人员隔离**：复检人 / 放行人不得与初检人相同。
- **分级放行**：
  - A 级（及断经）必须退修修复并在新版本复检确认；
  - B 级须复检确认，色差按标样让步或回染，长度不足可核减但低于订单最小长度禁放；
  - C 级复检确认或误判即可放行；
  - **照片缺失**必须复检补拍，否则禁止确认与放行；
  - 复检任务超 30 分钟未提交自动置超时并提醒改派（扫描周期 15 秒）。

## 数据存储

- `textile_qc.db`（SQLite，WAL 模式）：织机、颜色批次、布卷、检验版本、检验段、
  疵点类型字典、疵点、复检任务、退修工单、放行记录、提醒。
- `photos/`：疵点照片（演示数据为 SVG 占位图，支持 png/jpg/webp 等上传）。
照片接口校验人员身份、布卷归属并拒绝路径穿越。

## 测试

```bash
python3 -m unittest discover -s tests -v
```

覆盖 24 个用例：

1. **位置区间**：段越界 / 重叠 / 反向、疵点越段越卷、检验段仅限初检版本；
2. **版本关联**：退修生成 v2、修复记录引用原检验段、复检不得引用非初检快照；
3. **接收竞争**：双线程并发只一条成功、同初检人拒绝、open 任务唯一索引、超时改派、扫描幂等；
4. **放行条件**：A 级 / 断经强制退修、照片缺失拦截与补拍放行、长度不足低于最小值禁放、
   C 级与无疵点卷放行、已放行终态、放行人隔离；
5. **照片权限**：无身份 / 路径穿越 / 跨布卷拒绝，HTTP 层 409；
6. **HTTP 端到端**：页面与各 API、竞争接收、越界录入，以及 `--demo` 完整流程。
